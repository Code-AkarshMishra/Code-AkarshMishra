# Installation & Publishing Guide

This package is an overlay for your existing public profile repository:

`https://github.com/Code-AkarshMishra/Code-AkarshMishra`

## Important: keep the Next.js portfolio

Your current repository contains a Next.js portfolio application, including `app/`, `components/`, `public/`, `package.json`, and configuration files. This package only provides the profile README, profile assets, validation script, SEO guide, and `.github` automation.

Do not delete the existing app source or `public/` directory.

## Windows PowerShell installation

1. Download and extract the ZIP.
2. Open PowerShell in the folder containing both the extracted package and your local clone of `Code-AkarshMishra`.
3. Copy package contents into your repository root. `robocopy` copies hidden `.github` folders too:

```powershell
robocopy .\AkarshMishra-GitHub-Profile-SEO .\Code-AkarshMishra /E
```

4. Move into the repository:

```powershell
cd .\Code-AkarshMishra
```

5. Sync the existing portrait and screenshots into the new local media folders:

```powershell
python .\scripts\sync_existing_media.py
```

The sync script does not overwrite files already in `assets/photos/` or `assets/projects/`, so your own replacements are preserved.

6. Validate and inspect the change:

```powershell
python .\scripts\validate_profile.py --require-media
git diff --check
git status
```

7. Commit and push after reviewing the diff:

```powershell
git add README.md assets/ scripts/ .github/ SEO-SETUP.md MEDIA-GUIDE.md SETUP.md LICENSE-NOTICES.md CHANGELOG.md
git commit -m "Rebuild GitHub profile README and automation"
git push origin main
```

`robocopy` can return exit codes below 8 for successful copies with differences; those are not necessarily errors.

## Enable contribution snake

1. Open the repository's **Actions** tab.
2. Select **Generate Contribution Snake**.
3. Choose **Run workflow**.
4. After a successful run, the `output` branch should contain:
   - `github-snake.svg`
   - `github-snake-dark.svg`

The workflow also runs once daily. It uses the repository's `GITHUB_TOKEN` with `contents: write` permission to publish the generated images.

## Enable extended GitHub metrics and achievements

The Lowlighter Metrics action needs a personal access token for some user/account-level data that repository-scoped `GITHUB_TOKEN` cannot retrieve.

1. Create a GitHub personal access token using the minimum permissions required by the metrics features you enable. For public profile-only data, start with the least privileged token permitted by the tool's current documentation.
2. In the profile repository, open **Settings → Secrets and variables → Actions → New repository secret**.
3. Set the secret name to:

```text
METRICS_TOKEN
```

4. Paste the token only into the GitHub secret value field. Never place it in a README, workflow file, issue, or committed source file.
5. Open **Actions → Generate GitHub Metrics → Run workflow**.
6. Confirm the action commits `assets/github-metrics.svg` to `main`.

The Metrics workflow also runs daily. The achievement panel is generated by the Metrics plugin; the README separately links to the official GitHub achievements page.

## What “live” means on a GitHub README

A GitHub README is static Markdown. It cannot execute arbitrary browser-side JavaScript or call an API every second. The profile uses API-backed external image endpoints that may apply caching, plus GitHub Actions scheduled refreshes for generated assets. Treat the visuals as automatically refreshed, not second-by-second real-time telemetry.

## Validate the profile

```powershell
python .\scripts\validate_profile.py
```

The validator checks required README sections and local media references. Run the sync script first to copy the portrait and existing screenshots from `public/` into `assets/`. The original `public/` files are left untouched.
